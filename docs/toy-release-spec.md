# Toy 发布准备规格

日期：2026-10-20。基线：`f99bf7e`，已推送 `origin/main`；本轮分支 `codex/toy-release`。

目标是将现有 Godot 4.7.2 游戏推进到可在 Bilibili Toy 发布的候选版本。用户授权浏览器验证和发布前准备；正式发布、提交上线审核前停下等待用户决定。

## 保持与范围

- 保持现有角色、美术构图、玩法、成长数据和中英文内容。
- 以单线程 Godot Web 导出承载游戏，接入 Toy JS SDK，不重写玩法。
- 桌面鼠标/键盘/手柄继续可用；手机增加接菜拖动、送饭、思考、暂停及技能树操作入口。
- 压缩只发生在可复现的 Toy 构建暂存副本中，保留原始素材尺寸、透明通道和坐标约定。
- 标题页作者链接在 Toy 环境导航到 B 站空间 `2501012`，鸣谢页不添加游戏作者名。
- 本地存档保底，Toy 云存档按容量限制分块并提供明确的同步结果、恢复和冲突处理；不接排行榜作为首发前置条件。
- 结局纪念饭票在 App 用相册能力，普通浏览器用下载。
- 定向适配横屏、容器大小、安全区、声音解锁和失焦恢复。

## 成功标准

1. 当前源码生成独立的 Toy Web ZIP，入口、相对资源路径与体积满足账号后台限制；带构建与压缩统计。
2. 桌面浏览器真实启动、开始一顿、接菜送饭、结算、技能树、设置/暂停和重开恢复可用。
3. 触控事件夹具与窄屏浏览器检查覆盖拖动、按钮、取消和重新进入；物理手机未测时明确标记。
4. 平台桥接覆盖 SDK 缺失、游客/失败、云端分片损坏和恢复；真实 Toy 预览确认平台可达能力。
5. 最终包、源码摘要、浏览器证据和未验证项绑定同一候选版本。
6. 在正式发布/提交审核之前停下，交付候选 ZIP、预览入口、验证结果和发布所需资料。

## 分工与写入边界

- 整合：平台桥接、存档和结局适配、HTML 外壳、翻译、Git、浏览器与平台预览。
- 构建与压缩：`pipeline/build_toy.py`、`pipeline/toy_asset_profile.json` 及专用构建证据目录；不修改生产素材和编辑器项目。
- 触控：接菜与技能树输入脚本、独立触控 UI、相关定向验证；公共设置接口先沟通。

既有本地 Godot MCP 插件和编辑器配置独立保留；发行副本排除编辑器插件、测试和调试工具。
