# 助手分工切片规格 · 2026-10-19

基线：04d8ffa（0.4.0）。本轮目标是让助手服务玩家构筑，清除旧版自动化互相打架的规则。保留暖色手绘场景、小黑板、右侧乘区、软木技能树和已有六位助手美术，不重做整体视觉。已有玩家进度不改，所有测试使用独立 profile。

## 玩家决策与最终行为

- 招募每级增加一个同时出场名额；六个角色均可选择，可以休息。旧存档默认沿用前 N 位出场。
- 开饭前「助手分工」：补漏（默认）、指定配餐（需 fc）、补营养（需 nutri）；每位助手可独立选职责、配餐目标。配置保存，下顿生效。
- 配餐菜单只列当前档口/今日菜单能供应、饭盒能实际装配的菜谱；隐藏菜须已发现。禁菜或退技能导致目标失效时，显示原因并回到补漏；不暗中换一道最高价菜。
- 补漏按实际品级、热菜与顿悟价值判断；学会顿悟后，训练期青菜同样值得接。磁吸、跳接、捡菜、护菜遵守同一套食物判断；格格不会破坏青菜流，并新增质检特长：每盒第一份普通真实散菜升为优质；已银金、套餐、幽灵和极字不消耗机会，合成保留提升后的原料价值。
- 配餐优先补自己这盒缺的原料；完成订单便配送。营养师考虑已吃、等待、飞行和助手正在收集的菜，按 4:3:3 缺口补餐。过滤极字、装不下和玩家负责区域；助手不会因自动分散位置而交换已经分好的任务。
- 默认排队先进先出。助手盒预算为 max(3, 出场人数)，最多六盒（计算正在装、送、等待和保温中的助手盒），待机按等待时长公平领盒，不挤占玩家饭盒。
- 多 Agent 编排：保留每级跑速 +30%；完成一次有效配送的每种职责存一份接力，每类最多一份、共三类。下一盒玩家亲手送出的非空饭盒每份接力 +15%/30%，随后清空；助手盒不能消费接力或触发玩家连击。补漏需至少两份有效食物，配餐需完成指定菜，补营养需有至少两份所缺营养。界面说明储存与消费，有简短文字反馈。
- 异步调用：要求招募和服务器繁忙都已学会；保留馋值且助手不消耗它，玩家饭盒优先、各组内部先进先出。助手进食不凭空增长馋值。
- 自动推空盒、满盒回收分开开关；模型融合、Temperature、重新生成、过拟合可暂停，默认保持已购技能开启。这样单品拼盘、保温箱、青菜都可自由构筑。配置只影响下一顿。
- 缓存中继：单品拼盘 A → 首次给空缓存充能的余量套餐盒 → 单品拼盘 B，保留换菜接力并续连击；需要已学换菜能力，重复半盒套餐不能不断续连。
- 梯度裁剪和我去睡了保留现行全局保险效果、明确适用所有饭盒；不再强迫购买营养师/编排。收摊剩菜包括配送在途，同一盒按身份去重并排除已经结算的保温盒；普通和保温盒都只兑现一次已存接力。价格、等级、节点 ID 和画板位置保留，避免存档与既有投入损失。

## 公共接口（整合者负责 Game）

`Game.HELPER_IDS = [wen, pu, g, ke, zi, ge]`；`helper_capacity() -> int`。

存档可选字段（仍兼容 schema 3）：`helper_plan: Dictionary`，key 是角色 ID，value 为 `{active: bool, role: "sweep"|"recipe"|"nutrition", recipe: String}`；`automation: Dictionary`，key 为 `auto_push, auto_return, fuse3, temp, regen, overfit`、值 bool。缺字段使用旧行为默认；非法配置做有界过滤。

- `helper_config(id) -> Dictionary`：返回有效 `active, role, recipe`，以及 `requested_role, requested_recipe, reason`（无失效则空串）。出场超额时按 HELPER_IDS 顺序保留前 capacity 个，未配置角色默认原前 N 位。
- `active_helpers() -> Array`：有效出场 ID。
- `set_helper_config(id, active: bool, role: String, recipe: String) -> bool`：超额或未解锁职责/无效菜谱返回 false；保存并 changed。
- `helper_recipe_options() -> Array[Dictionary]`：`{id: String, name: String, kind: int}`，可用普通配方；过滤禁菜、未开档口、无法装配进当前饭盒的配方。
- `automation_enabled(key) -> bool`：拥有对应 stat 且开关非 false。
- `set_automation(key, enabled) -> bool`：仅允许上述六项拥有的技能；保存并 changed。

技能数据新增 `crew_relay` 每级 +0.15，orch 其他效果保留。async 新增 `require_all: true`（Game 可见性/购买遵守）；hire/clip/sleep 新前置分别 start/hire/hire。节点坐标不变。

运行状态冻结为开饭时配置。运行中的每个助手 dictionary 有 `role, recipe`（recipe 是 kind int，缺省 -1），饭盒携带 `crew_id, crew_role` 以及用于确认有效任务的字段。运行实现可加私有辅助函数，报告稳定测试接口。

## 分工与验收

整合者：Game 配置/存档、集成、本规格、字体/翻译合并、运行验收、提交推送。

运行代理：仅 canteen_run.gd 及新增运行 helper policy/feedback 脚本；实现任务、接力、公平队列和开关读取，保留玩家手感及现有计分公式。不得修改 Game 或 UI。

呈现代理：tree_screen.gd、新 crew_planner_panel.gd 及专属 UI 测试；现有角色图像配暖色纸笺，入口不拥挤，单弹窗、键鼠/手柄/Esc/焦点恢复，简洁职责说明、当前任务、休息/出场、配餐图标、自动操作页；不要改旧菜单/技能票主题。新增英文映射另存 build/helper-ui-en.json，交整合者合并。

数据/验收代理：build_tree.py、skill_tree.json、helper_strategy_test.gd/.tscn、新 helper设计说明；节点 ID/价格/位置保持；新增文字英文映射另存 build/helper-data-en.json。独立验证青菜训练/金牌优先、禁菜/缺料/装不下、全员同任务不过度拥堵、FIFO/异步、接力不污染连击、持久化/退点回退、关闭自动行为。

GPU 捕获、导入只由整合者执行。最终冻结源后执行既有回归和本次规则/真实输入 UI 测试，查看中文/英文 1920×1080 与 960×540，验证玩家存档未改。测试证据区分规则 fixture、自动游玩、视觉检查；不以自动跑分替代真实手感。

素材使用已有六位助手的站立/跑步/庆祝/睡觉图。台词先采用限频、事件相关的短文字；本轮无需为已有合适的角色图重复生图或堆叠语音，以免重现疲劳问题。
