# 玩家青菜流与可行构筑分析

分析日期：2026-10-19。只读快照：`build/qa/player-build-analysis/save-snapshot.json`，根代理于 18:50 复制。本文没有修改游戏数值、生产源码、真实存档或用户设置，没有跑 GPU 或自动通关。

结论：青菜流有清楚的系统支撑，也有用户亲自玩出的正面反馈。现有机制可以推导 **六种不同操作循环**，但证据还不足以称为“六种成熟且平衡的通关流派”：只有青菜流得到本次玩家反馈；单品轮换、保温收尾、均衡评鉴有可复现的数值基础；助手路线主要证明机制能协同，捕获效率仍待实玩；高温随机路线在分析中发现并由根代理修复了变菜后容量边界，仍需整局与真人验证。

## 2. 青菜流为什么成立

### 2.1 第一道乘法是“确定供应”，不是面板价值

炒菜 1 级只有青菜与番茄炒蛋，基础权重各 3。ban egg 后，无论“阿姨关心”是否增加青菜权重，余下的都只能是青菜。10,000 次实际 `_stall_kind("wok")` 均为青菜。

| 炒菜等级，仍只 ban egg | 不缺蔬菜时青菜概率 | 最缺蔬菜时青菜概率 |
|---|---:|---:|
| 1：只剩青菜 | 100% | 100% |
| 2：加土豆丝、红烧肉，各权重2 | 3/7 = 42.86% | 6/10 = 60% |
| 3：再加宫保鸡丁，权重2 | 3/9 = 33.33% | 6/12 = 50% |

因此“故意不升炒菜档口”是实质构筑选择。三级仍能用四个 ban 把其余菜全划掉，但会占满全部禁菜位；一级只占一个。每个开放档口必须留一道，旧档不合法的 ban 会被过滤；LoRA 按真正生效的 ban 数加成。

快照不是只开炒菜的单档口配置，而是主食4 / 炒菜1 / 点心3 / 油炸3 / 甜品2，所有五档都开。并发5加五个档口，触手上限截为8，按固定顺序分配为：点心2、炒菜2、主食2、油炸1、甜品1。不是每档八只手。

`canteen_std=3` 让**每次任一档口出勺**另有45%概率送一份青菜；`batch=3` 让一勺原本随机1–3份另有75%概率加1份，因此一勺平均2.75份，并非整勺翻倍。API5使出餐速度系数为 `1.12^5 = 1.76234`；高峰期间速度再乘2.5，但每轮仍有0.45秒抬勺时间。

用周期近似 `每只触手勺/秒 = 1 / (2.15 / 出餐速度 + 0.45)`，再加每档额外45%青菜，得到普通约5.50份青菜/世界秒、高峰约9.75份。105秒内高峰计划约56秒、非高峰49秒，对应约815份**抛出青菜**。这是供应量近似，忽略首轮计时、跨高峰边界、逐帧量化、场上160件上限；不代表接住或吃掉815份。

### 2.2 12口启动后，青菜从0变14

快照拥有顿悟1、预热3、回甘4：门槛 `30−6×3=12`；顿悟后每份青菜基础值 `6+2×4=14`。顿悟前强行吃的12口没有 token，不调用正常 `_bite`，因此没有 MTP，也不增加流式输出的付费口数；每口还有0.5秒咀嚼暂停。吃饭12级提供 `2×1.25^12=29.1038` 咀嚼单位/世界秒，但不会去掉这段启动暂停或每盒0.55秒开饭动作。

SFT5是40%优质判定，LoRA因一个有效 ban 加3%，共43%；DPO3是**在这43%内**有60%变金。不是全体60%金菜：

| 从档口直接抛出的青菜 | 概率 | 顿悟后裸价值 |
|---|---:|---:|
| 普通 | 57% | 14 |
| 银色优质 | 17.2% | 28 |
| 金牌（FP32） | 25.8% | 70 |

未融合、未过拟合前，平均品质倍率为2.204，青菜平均裸价值30.856；MTP4使每个正常付费口额外+4，即34.856。暴击15%、暴击倍率2.5，平均暴击因子1.225。金饭盒给全局×3；没有隐式全屏吸附。

### 2.3 ban egg 还保护“菜本身”，防止自动合成吞掉回甘

青菜作为套餐原料时，`_part_value` 使用 `max(VALUE[veg],1)=1`，**不会继承顿悟后的14**。合成保留品质/高温和RAG，但不保留青菜单独吃的回甘基础值。

快照 Prompt3、RAG1下，一份金青菜与金番茄炒蛋合成，原料为 `(1×5+2)+(3×5+2)=24`，一级套餐倍率1.8，最后43.2；分别吃的裸价值是70+15=85，且分别吃还有两次MTP。普通二者合成只有 `(1+3)×1.8=7.2`，单吃17。吃饭吞吐不足时合成的一口压缩仍有用，但此档吃饭12级、青菜价值14，**保护散菜比盲目合成更符合主轴**。

当前 `temp=0` 是有利的简化：未顿悟时 Temperature 可能把青菜变成土豆丝，拖慢12口启动。顿悟后 Temperature 会让青菜留在原菜、升品质并加热；这是可测试的后续变体，而非当前玩家收益来源。过拟合已买：顿悟后15%非青菜散菜变普通高温青菜（裸值21），会丢掉原菜/原品质，有时也会拆散其它套餐目标。

### 2.4 满盒、连击、流式与收尾形成后段放大

当前8格盒，Prompt3让满盒同一种真实散菜获得+30%；不同品质可以混装。光学压缩3的+60%、上下文填满的+25%与它相加：

`盒内加法池 = 1 + .60 + .25 + .30 = 2.15`

多轮对话1实际每步+10%，第13个连续合资格盒达到 V4 上限×2.2。连击在**亲手送出时**冻结，助手盒不推进或打断。单品满盒与“至少两份二级以上真实套餐”都可连击；不是随便满盒都可以。

快照流式3、首Token延迟2：`S(n)=min(6.5,1+.6×log2(1+max(n−20,0)/20))`。

| 正常付费口数 n | 20 | 100 | 200 | 600 | 1000 |
|---|---:|---:|---:|---:|---:|
| 流式倍率 | 1.00 | 2.393 | 2.993 | 3.944 | 4.386 |

×6.5只是上限，此配点要约11,495口才触顶，不能拿6.5当普通105秒局的常驻倍率。顿悟后第200口、满青菜盒且连击已到×2.2、不算馋与整顿加成，一口金青菜的期望暴击收入为：

`(70+4) × 2.99316 × 2.15 × 2.2 × 3 × 1.225 = 3,850.17`

这是条件单口例子，绝非每口都满足，也不是780万分复现。

服务器繁忙5的最大馋倍率为×4，时间常数3.5秒。普通盒只拿实际空腹积累 `1+3×(1−exp(−t/3.5))`，不能假设全程×4。异步调用让助手盒不消耗**已有**馋，也不给助手盒这项奖励；助手一直在喂时，鱼没有空等，馋不会继续增长。

现存保温箱+Final1在收摊时对预留盒给×3、自动满馋×4；EOS3让该盒最高裸价值一口总共算8次（额外7次），随后再乘整顿均衡/评鉴。Best-of-N只按当前裸盒价值选盒，不考虑未来连击/均衡/EOS形状；也不会主动修复口数损失。这些都是当前档已经拥有的放大器，不能把全部高分归给青菜一项。

### 2.5 它有代价，不是数学上的无限

当前有模型融合。三普通青菜42裸价值变一银28；三银84变一金70。两种融合都少14裸价值、少两次MTP、少两次流式口数，但腾格并提高每盒/每口密度。

固定种子20261019、实际 `_catch` 规则、只接青菜，10,000盒8格满盒抽样：平均需14.0308份输入，中央値14，90分位18；平均盒裸价值390.5762；每输入保留价值27.8371，付费口数/输入为57.02%。相比不融合的30.856/输入，价值少约9.8%；加MTP后且尚不计流式差异，约30.118/输入对34.856，少约13.6%。代价换来了更昂贵的每盒，保温/EOS可能因此受益；应实测“去融合”是否更好，不能直接下结论。

概念漂移把每份青菜计0.5荤+0.5素，**不补主食**。纯青菜无漂移时均衡×1；有漂移仍只有 `balance_score=1/3`，快照整顿倍率约1.33679。按营养计数，40份主食+60份漂移青菜才到4:3:3，基础上限×2.75；豆浆等招牌累计再加最多0.5，可到×3.25。快照有5个助手和主食/豆浆招牌，正好可能填补主轴遗漏，但实际营养曲线未记录，不能宣称已经精准均衡。

另外，提示词注入会在合成时藏走一片真实青菜，已顿悟时同样按原料1而非14处理；满盒单品本身不发生套餐合成，所以保持单一菜盒可避开这个损耗。V4局有105秒世界时长，思考只减慢世界，不无限造世界时间。“无限吃青”是持续供应和连续回盒的体验，不是无上限时长/增长。

## 3. 六种实际不同的构筑方向

这些不是六个完全互斥的职业。金饭盒、吃饭速度、基础品质是共用底座；区分来自玩家追求的反馈目标：**过启动门槛持续吃同菜 / 按盒换菜 / 押最后一口 / 一局做多种 / 把接菜工作分出去 / 根据随机变菜临场配盒**。

### 3.1 单品轮换的计算与装盒陷阱

示例 Prompt3+Memory2：换菜盒加法池 `1+.60+.25+.30+.20=2.35`，同种连续盒则2.15；不是在最终收入上另乘1.2。多轮对话3实际每步+20%，V4第13盒起×3.4。每种品质都可混在同种菜盒里；鬼菜不破坏纯度但不填满格子。普通杂盒中断轮换；Memory减轻连击中断并不保留“上个单品种类”。

包子与鸡腿均单格，所以4/6/8格都能填满。白饭双格：2×2放两碗、2×4放四碗能满，**2×3每行只能放一碗，三碗放不下**。因此不推荐六格阶段的纯白饭拼盘。增加饭盒尺寸也会降低送盒频率、拖慢建立连击；示例用8格是完整参考配置，低等级时可先试4格轻快循环，不必抢升显存。

### 3.2 保温可以是不同玩法，但“所有大倍率都满”不是合理入门配点

深度思考套餐=`白粥(3)+冰淇淋(6)`，隐藏菜固定神级，压缩后仍1格、1口；AGI套餐1使倍率3.6，普通原料裸值32.4。同等级RAG1，两份金食材若已另外买FP32是 `(3×5+2+6×5+2)×3.6=176.4`；**表中394万示例没有买FP32**，按它自己的金牌×4应为 `(12+2+24+2)×3.6=144`，别拿升级后的数字算低预算配置。

示例Final2→保温×4，busy5→满馋×4，EOS3→最好一口总8次；还要乘材质、当时流式、盒池、整顿奖励。EOS最好口以裸 `_item_value` 选，不看招牌补值。

更复杂的“满血版”由家常便饭+快乐套餐+豆浆油条+下午茶组成，10份基础原料总和27。AGI套餐1是97.2，**不能把各层套餐倍率连乘**；思维链靠真实嵌套合成另外进盒池，最多+90%。夹具完整平铺原料能合成它，记录5次嵌套、实际截到3次奖励，但这不证明在当前8格盒中任意接菜顺序都能装完。应按小套餐→大套餐分批规划。AGI套餐5累计技能本身要174,762,500，不应给这位700多万现款玩家推荐“直接点满”。

### 3.3 评鉴路线存在可做的九种，吃掉才算

表中菜单保留：碳水炸弹、白粥馒头、番茄炒蛋配青菜、豆浆油条、下午茶、家常便饭、饭团便当、炸鸡配炒饭、早点铺。九种原料在对应档口等级与四个ban后都存在。比如家常便饭会消耗番茄炒蛋配青菜，若想两种都算，必须分别做一份、各吃一次，而非只把前者一路升级。

critic1+bench2使每种从第五种起+8%；5/8/9/12种分别×1.08/1.32/1.40/1.64。RLHF4上限3、宪法AI降低偏食曲线惩罚（不免营养要求），13份相关招牌饮品/白粥可把加成累到+0.5；理想4:3:3且9种被吃掉时，整顿×3.5×1.4=4.9。这是**条件上限**，不是这条路线默认倍率。第五种才开始奖励意味着它有前置成本；速刷4种没有评鉴加成。

### 3.4 助手路线不是“再来五个玩家”

助手自己带盒，不占玩家空盒；桌上待吃队列达到3盒时停止新取盒。满盒送；半盒且4秒没进菜会送；有任意菜但9秒没进菜也会送。点单将最高静态价值、可制作套餐的原料权重×3；营养师将当前最缺类别×2.5，不保证完成配方或准确4:3:3。加权基数是静态 `VALUE+0.5`，并不随顿悟回甘/品质/高温实时重估。

需要纠正旧审计的一处过度概括：谱谱**不吸**青菜，克劳**不捡地上**青菜，格格会把青菜拍走；但不是这三人统一在所有接菜路径绝对拒收。实际 `_crew_catch` 在已顿悟后允许空中青菜落进助手盒。本次纯助手例子主动ban青菜，避免依赖这个复杂分支。

助手盒不触发玩家单品/缓存/换菜，也不推进连击。sleep只对剩下的菜使用0.5盒倍率、没有流式，也没有满盒/馋/连击那套盒奖励，再参与整顿均衡/评鉴；可以止损，不能让无限排队等于全部吃完。clip须完整吃完至少5盒，才将最差20%盒的实际收入补到均值，既吃不完又想拿clip不成立。

### 3.5 随机路线有可解释收益，也有实质未完成之处

示例temp4=32%、hot3使高温×2.25、halluc2=16%。无“接近配方保护”时，番茄炒蛋基础3，32%升级为高温红烧肉5×2.25，单项同品质期望比原菜为 `(0.68×3+0.32×5×2.25)/3=1.88`；布丁3升级高温双皮奶4时为1.64倍。实际保护某份待完成原料时会跳过变菜，这不是全程常驻收益。

`_upgrade` 不要求目标菜已经由档口等级解锁，所以一级炒菜也能变出二级肉菜；ban目标菜会阻止该升级。这样“低级档保留单一基底，随机越级”是不同于直接升满档口的路线。幻觉是普通品质高温鬼菜，0格、有吃饭成本，不能合成原料；其收益因随机种类而异。

V4涌现需另外4,612,500；检测到至少3份真实高温散菜时，每次检查25%变神级乱炖，普通套餐先合成，可能先耗掉这些散菜。连续3/5/8次**满足条件**且未成功检查，至少成功一次概率约57.8%/76.3%/90.0%。不能把它写成“每接12份必出神级”，也不能把鬼菜计入3份。

分析发现过容量边界：4格盒里3个包子，单格鸡腿通过 `_accepts`；旧逻辑随后把鸡腿变双格汉堡，盒内占5格，`_pack`为空。根代理在本轮修复：先验证变菜后装盒/合成，放不下时保留原菜并升品质、高温；留有两格时仍可变汉堡。夹具将proc强制1只为隔离分支，分别验证这两种结果，不代表合法100%变菜配点。修复没有调整概率/倍率，也不构成对随机流整局强度的验证。

## 4. 不应硬凑的“流派”和最小补充

**缓存目前适合作为配套节奏，不足单独算第七条。** 空至少2格且含真实套餐的亲手小盒，存下一满盒+15%，加到盒池，不是最终×1.15。若满盒已有池2.15，收益只提高约6.98%；送一个小套餐可能同时损失连击和单品轮换。优化做法是小盒装两份二级以上套餐：能保连击并充缓存，但仍重置单品轮换。

当前可达的合法送餐状态里，**缓存+15%和换菜+20%不能同盒同时获得**。充缓存的小套餐盒把前一单品类型重置为-1；下一满单品消耗缓存并建立单品类型；再下一换菜时缓存已空。纯规则函数可以对人工拼出的“缓存有且已有前一单品”返回两者，但真实提交序列不能到那个状态。夹具遍历代表性提交状态确认了这一点。鬼菜、助手盒都不能绕开。

“红烧肉招牌”“汉堡招牌”“冰淇淋招牌”是同一种高值慢供策略的换皮，不各算一流派。招牌mult实际上以原始裸值增加固定差额：金红烧肉FP32裸25，招牌再加7.5，共32.5，而非25×2.5=62.5；相关整档还慢30%。不能把品质倍率与招牌mult无脑相乘。

要把六个方向变成六种成熟玩法，最少需要以下工作；除根代理已完成的变菜容量正确性修复外，下面均为建议，没有实施数值平衡或新增机制：

1. **落实随机变菜装盒的实际回归**：本轮根代理已按最终结果验证空间，放不下回退原菜并升品质/高温；规则夹具覆盖两条分支。还需在整局真实接菜中确认表现，再讨论随机流的强弱。
2. **用同预算做真人比较**：青菜、轮换、保温、评鉴各3局，另测助手/随机；记录付费口数、每菜输入/吃掉数、每盒送达顺序、保温/EOS占比、首顿悟时间、营养轨迹。现存 best_run 无法归因。比较评分、接菜压力、失败可恢复性，不只比理论上限。
3. **让已有路线能稳定控制**：最小的构筑工具是可选择暂时关闭已买的自动送满盒（保温/复杂配方）、融合（口数路线）等行为，或提供配点/今日菜单预设。当前可用全额回滚试验，但买错之后无法单独停用一项，试错成本主要是操作与认知。
4. **若想让缓存成为独立操作路线**：首先明确它和轮换是选择还是组合。若设计意图是组合，可让“专门充缓存的小套餐盒”不覆盖前一单品类型，再从低额开始验证；这是规则调整，必须另行验收，不能把不可达组合写进现有说明。
5. **让助手与菜谱路线更可靠**：优先给点单一个可选目标/职责，而非仅按最高静态菜值；让UI显示这一局已吃套餐种类。无需先添加大量新技能。只有真人确认全程工作量与收益取舍后，才决定是否补数值。

现有已证机制并不缺“六个名字”，缺的是路线可控性、边界修复和同预算实玩数据。应保留青菜流的爽感作为成功参照，先把其它路线做到同样容易理解和稳定执行，而不是先削掉玩家找到的乐趣。
