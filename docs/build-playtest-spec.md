## 本轮问题

六条循环分别是顿悟青菜、单品轮换、保温收尾、均衡评鉴、助手分工、高温随机。历史分析提出的自动技能开关、缓存中继、助手指定订单/营养职责和评鉴数量显示已经上线。仍需确认随机改菜全程装得下，以及让新局记录足够解释收益来源。

本轮交付：

1. 检查 Temperature 与重新生成两条改菜入口；用普通出勺、真实下落接触和正常结算跑完整局，连续检查饭盒容量。分支夹具与整局结果分开记录。
2. 增加只在本机保存、独立于进度存档的最近对局记录：开局构筑/累计购点成本、输入菜和吃掉菜、付费口数、顿悟时间、送达/开吃顺序、营养轨迹、保温/EOS/全顿倍率。
3. 给出可复用比较工具与真人记录规范。机器人结果明确标记，不能作为真人操作压力、乐趣或六路线平衡的证据。

记录不得消耗随机数、改变计分/自动行为、在逐帧热路径写磁盘，或向网络发送数据。测试使用独立 profile，验证真实存档和设置前后字节一致。正常局和测试局的记录分开，保存数量和事件数量有上限。

## 成熟标准与后续决策

| 方向 | 必须验证的循环 | 优先观察的失败 |
|---|---|---|
| 青菜 | 启动顿悟→稳定青菜口数→连续满盒 | 训练被变菜打断、融合减少付费口数 |
| 轮换 | 单品 A→单品 B；可插入一次缓存套餐 | 跨档接菜压力、杂菜断线后能否恢复 |
| 保温 | 普通餐维持吞吐→预留高价值盒→EOS兑现 | 等原料/留盒损失是否超过收尾收益 |
| 评鉴 | 真正吃掉新套餐→补营养→整顿倍率 | 做出但未吃掉、被嵌套合成吞掉新种 |
| 助手 | 分工有效交付→玩家消费接力 | 订单长期占位、助手抢料、排队吃不完 |
| 随机 | 低级供给→变菜/升品质→临场配盒 | 装盒越界、纯度损失、收益不可理解 |

真人比较固定游戏版本、版本阶段、总投入上限、操作者和输入设备；记录实际花费与剩余预算，不把不同花费叫“同预算”。先青菜/轮换/保温/评鉴各三局，再助手/随机，轮换测试顺序。记录一局的主方向及混搭；不能从分数自动猜流派。额外手记：操作压力 1–5、断线后的恢复是否清楚、最爽/最挫败的时刻。先解决不可控/不可读问题，再决定补偿数值；不先削弱用户验证过的青菜爽感。
