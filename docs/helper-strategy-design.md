# 助手分工：规则、构筑与验收

基线 `04d8ffa`，2026-10-19。对应 [helper-redesign-spec.md](helper-redesign-spec.md)。本轮保留已有六位助手、暖色手绘场景和技能票布局；目标是让助手可服务玩家指定构筑，并解释自动行为的取舍，不是宣布六种玩法已经平衡。

## 数据和存档兼容

本轮没有新增节点。75个节点（含根）的 ID、名称、价格、成长、最大等级、版本环和坐标逐项与基线相同；已有技能等级继续有效。

| 节点 | 最终规则/数据变化 | 玩家得到的控制 |
|---|---|---|
| hire | 前置从 skills 改为 start；仍每级+1 helper | 买的是同时出场名额；六人自由选择或休息，不必先买自动送盒 |
| orch | 保留 helper_speed 每级+0.3，新增 crew_relay 每级+0.15 | 不同职责各完成有效配送，为下一盒亲手送餐积累接力 |
| fc | ID/价格/效果属性不变，改为解锁指定配餐职责 | 每位助手选择具体目标；不再暗中追最高静态价值套餐 |
| nutri | 原有解锁关系和属性不变，说明更新 | 参考已经吃、等待、在途、保温、手持和正在收集的食物补缺 |

| fuse3 / temp / regen / overfit | 数值不变，说明开关 | 可以暂停会打乱口数或菜品的自动效果，下顿生效 |

schema仍为3。`helper_plan`、`automation`是可选字段，旧存档缺字段时沿用前N位助手、默认补漏和已购自动技能开启。开饭前配置可持久保存；开饭时冻结，运行中的助手/行为不会随菜单后台变化。

超额出场保留有效顺序内的前capacity位，设置接口会拒绝新超额选择。休息操作先落实所有默认出场成员，避免一个人休息后另一个默认角色悄悄补位。菜谱/角色技能失效时保留用户请求，返回有效补漏职责与原因；材料恢复或技能重购后可恢复原请求，不能偷偷换目标。完全退技能后没有助手出场，未拥有的自动技能也不能通过开关生效。

### 固定画板而非冻结生成结果

`pipeline/build_tree.py` 的 `BOARD_POSITIONS` 保存经过评审的75个位置，布局与解锁前置分开。正常生成不再调用依赖父节点的自动松弛；也不读取已生成 `skill_tree.json` 来决定位置。即使输出文件删掉再生成，也得到同一画板。

节点ID集合与位置表必须完全一致，新增/删除ID会明确报错，要求主动审查布局。原径向/松弛函数仅保留供未来明确的布局工作使用。数据比较和连续生成验证分别检查所有旧字段与输出字节，不会因为一条前置线变化重排整个技能树。

## 三种职责必须改变实际决定

**补漏**根据实际品质、火苗和顿悟价值选食物，仍受移动距离、落点时间、可装盒和玩家负责区域限制。学会顿悟后，训练期青菜也有未来价值，不能被旧拒菜逻辑排除。谱谱的吸引、克劳的地面拾取、小G的跳接使用相同可接判断；格格保留青菜，不再破坏这条构筑。

**指定配餐**按自己盒内已有原料与嵌套套餐扣除缺项，只收仍缺的材料；候选食物还要保持目标有实际可装配的路径。目标列表先经过开放档口、有效禁菜、已发现隐藏菜、当前盒宽和压缩的过滤，然后用实际自动合成与两行装盒规则搜索可行收集顺序。只有菜单能出所有原料仍不够：四格盒无法逐步装出食堂全家福，八格才可行。无指定配方的乱炖等特殊产物不作为订单。

完成目标即送，不要求满盒。未完成订单不会按普通杂盒超时送走；这确保语义一致，但稀有/分散原料可能使它长时间占用一个配送名额。因此“菜单可制作”不是“本局肯定完成”。

配餐盒保护需要的原料，不让Temperature、过拟合、融合、涌现、大杂烩随机改变或吃掉它们。正面联动保留：投机解码优先补指定目标缺项，并验证接收/后续合成；提示词注入不吞掉目标仍需要的青菜。保留品质、热菜和格格质检进入套餐的价值。玩家盒及其它职责仍按各自启用的普通规则处理。

**补营养**以主食:荤:素=4:3:3的缺口选择类别。预测包含已吃计数、当前吃饭的剩菜、等待队列、配送途中、保温盒、玩家手中及助手货物；同一个饭盒在多个数组中的引用只算一次。一次全体规划中，第一位助手锁定食物后，先把该食物加入预测，再决定下一位，避免每位都追同一缺口。已顿悟青菜的概念漂移也按实际0.5荤/0.5素预测。

规划后的目标始终属于原来的助手；不能为了维持左到右队形，交换两个不同订单的落点。相邻目标保持空间间隔，助手避开玩家当前通道。预测依然是启发式：没有承诺每次投掷都接到，也没有预测将来尚未生成的食物。

## 六位角色与接力

问问保留较宽接菜范围；谱谱吸引可接的食物；小G较高处跳接；克劳拾取附近符合职责的落地菜；双子跑得更快。格格新增正向质检，避免“拍极字”在正常几乎无极字局里没有作用：

- 她每盒第一份普通、真实、非套餐且非极字的散菜升为银牌；每盒一次。
- 已有银牌/金牌、鬼菜、套餐、极字不消耗机会。新的饭盒重新有机会。
- 训练青菜可升银；合成之后仍保留原料的银牌价值。

格格仍能拍极字，但不会拍走青菜。她适合少量高价值原料的配餐，也能支持青菜路线；具体每局增益取决于第一份普通菜是什么，不能把全部菜都按银牌估值。

多Agent编排的接力以**有效配送**为依据：补漏至少两份有用真实食物；配餐必须真正完成指定菜；营养要交出至少两份当时缺的营养。鬼菜不能刷有效份数。未顿悟、没有顿悟训练价值的裸青菜，即使可以留作注入材料，也不能仅凭两片就刷补漏接力。

三种职责各最多存一份，重复同职责不叠加。下一只玩家亲手送出的非空饭盒，一次消费全部，1级每份+15%、2级每份+30%，加到原盒加法池；三种齐备最多+45%/+90%。这不等于所有玩家饭盒永久最终×1.9。助手盒、外卖盒、空盒不消费；助手任务也不推进、破坏或伪造玩家单品/套餐连击。

接力在亲手提交时存入饭盒，由正常进食或保温箱最终结算兑现；共用盒加法池，不能在普通盒重复加、也不能漏掉保温盒。收入明细的规则加成份额包括这份接力，跟随保温倍率，但不把整盒收入都算成接力收益。

## 队列和预算

默认先进先出。异步调用要求招募与服务器繁忙同时学会，改为玩家盒优先、两组内部先进先出；助手盒既不消费也不享受馋，助手吃饭期间不会凭空增加馋，已存馋可留给玩家盒。高频玩家送盒可能推迟助手饭盒，这是异步优先级的代价。

最终预算是 `max(3,本顿实际出场人数)`，并非早期规格的固定3。正在装、配送、等待、保温的助手盒都占名额；正在吃的盒已释放名额；同一盒的别名去重。六人出场时六人都可以开工；只有空位不足时才等待。等待者按累计等待最长先领盒，避免固定ID顺序让后排角色一直没活。助手自带盒，不取玩家空盒；Best-of-N可把助手好盒留保温，但该盒继续占一份助手预算。

「我去睡了」收摊统计桌上、正在吃、配送在途、玩家手里与助手盒内的剩菜。多个容器引用同一饭盒，只结算一次；内容一样但确实是两盒，则分别结算。保温箱已按保温规则结算，其它容器仍持有这个盒的引用也不能再走半价剩菜结算。剩菜保留食材真实品级与热菜价值，按半价计入整顿加成；不沿用流式、盒、连击或盒内接力奖励。

## 玩家可以怎样使用

| 构筑 | 分工与自动行为选择 | 取舍 |
|---|---|---|
| 青菜顿悟 | 玩家守一级炒菜档，ban蛋；补漏助手可接训练青菜，营养助手补主食/荤，格格不破坏青菜；可暂停融合/Temperature/过拟合来保口数和启动材料 | 助手预测不会创造当前菜单没有的营养，仍需保留供给；融合关闭是否更高分要实玩比较 |
| 套餐/保温 | 为1–2人指简单可达套餐，玩家筹备大盒；格格让首份普通原料升银；关闭玩家满盒回收，手动留保温；保留投机解码帮指定订单补缺 | 多人同单会争同一类原料，稀有订单可能占位很久；不应六人都点最难配方 |
| 单品轮换 | 玩家只送纯单品，助手补漏/配餐/营养提供三种接力；按需暂停会改菜名或吃掉份数的自动效果 | 助手不会替玩家制造单品连击；接力只给下一盒，不是永久增益 |
| 单品—缓存—换菜 | 已有Prompt、压缩、Memory：送满单品A；再亲手送一个含真实套餐且至少空两格的小盒，给空缓存充能；再送满单品B | 中继只在首次充空缓存且前一盒为单品时保留换菜与连击；第二个小套餐不能无限续线。B可同时得到缓存和换菜奖励，普通杂盒仍会断开 |
| 轻操作/全局保险 | 增加补漏助手，启用自动空盒和满盒回收；clip/sleep可直接从hire取得 | clip须至少吃完5盒；sleep是半价值收摊保险，不能等价于正常流式/整盒收益 |

上一轮构筑分析曾证明“缓存与换菜同盒奖励不可达”，针对的是旧规则。本轮根代理明确新增一次缓存中继，上述A→小套餐→B现已可达；不要把历史报告当作本轮规则说明。助手接力和这条玩家缓存桥接是独立来源，不应混为同一个状态。
