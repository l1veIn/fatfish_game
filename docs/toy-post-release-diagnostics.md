# Toy 上线后诊断（2026-10-21）

线上入口：https://www.bilibili.com/toy/fatfish-free-lunch/index.html 。用户已自行发布。

## Wi-Fi 加载中断

- Chrome 正式页两次出现 `TypeError: network error`，加载停在约 50,611,928 / 80,047,606 字节。
- 引擎文件 `index.wasm` 完整获取，39,514,754 字节，SHA256 与 RC6 完全一致：`fc74679e3b97f76878947fcd4fbe1268cbfa6188182a2e33bbc3f5dc9bfa57d0`。
- `index.data` 的常规下载在 90 秒时仅获取 4,406,667 / 40,532,852 字节，范围下载也在部分区间中断。
- 用户切换手机流量后可以进入游戏，确认问题与 Wi-Fi 路径有关。
- 只读登录 iStoreOS/OpenClash 检查：当前普通 DNS 把 `www.bilibilitoy.com` 分配到 `163.181.39.*`，HTTP 头显示日本 CDN（`jp10/l2jp3`）。当前 nameserver 使用经代理查询的 Google/Cloudflare DoH。
- 在同一软路由上向 `223.5.5.5` 查询，得到国内 `123.138.126.*`。用单次 curl `--resolve` 指定其中一个国内地址，证书校验保持开启，完整获取 40,532,852 字节，仅用 **1.095358 秒**（约 37 MB/s）。这只是诊断请求，没有修改系统 DNS、代理规则或网络配置。
- 推断：此 Wi-Fi 下的海外 DNS/CDN 调度是加载失败的主要原因。适合的后续措施是对 `bilibilitoy.com` 设置国内解析策略并维持国内直连，不需要关闭全部代理。

原始下载头、范围请求结果保留在本地 `build/qa/toy-published-startup/`。没有改动路由器配置或重启服务。

## 本地加载器修复（尚未上传/更新线上）

网络异常暴露了两个独立的加载体验缺陷：

1. `setLanguage()` 在引擎资源尚未加载完成时建立“正在检查云存档”提示，此时尚未调用云读取。改为只更新已存在的同步提示。
2. 固定 Godot 4.7.2 Web 模板的 tracked ReadableStream 以及 WASM/初始化嵌套 Promise 没有完整传递 rejection，可能令 `startGame()` 永久 pending。构建管线对固定签名做最小补丁，将下载、编译、模块和文件系统错误传给外壳；模板变动则拒绝构建。

外壳显示真实 MB 下载量；45 秒没有进展时允许继续等待或重新加载；失败时结束进度动画并提供重新加载按钮。正常进展恢复时自动收起停滞提示，不强制中断慢速设备。

候选：`build/toy-final-rc7/FatFish-0.4.2-toy-compressed.zip`，48,085,009 字节，SHA256 `650fa59c714de9dfd03448d81dc3f9ac8805bbb4f29c77a1eabfa2f464f9dae3`。

随后本地 RC8 合并了一级助手送餐后停滞修复，作为更新的候选；包与封存记录见 [助手修复验收](helper-return-bug-validation.md)。RC7 仅保留为加载器诊断阶段的记录。

验证：桥接 20 项、加载器故障注入 8 项、外壳状态 3 项、构建打包 5 项均通过；完整构建、字体和纹理检查通过。Chrome 本地候选真实加载到“进入饭堂”，云读超时不阻止启动。故障注入只替换网络响应和初始化函数，没有运行或覆盖生产玩家进度。

## 手机全屏截图（已定位，尚未修改）

源码确认，HTML `#game` 用 Toy/env safe-area 同时缩进整个画布的 top/left 并缩小 width/height。Godot 又保持 1920×1080（16:9）比例，在超宽手机屏幕上另加左右留边，两层叠加会明显压小游戏面积。截图与这一机制相符，但没有拿到该真机的实时容器状态，不能仅凭截图断言 Toy 是否已经报告 immersive=true。

右上角“⋯ / ×”是平台控件。即便容器进入沉浸模式，刘海/平台操作区也应保护按钮；这不要求整张游戏背景都向内缩进。

后续应让背景铺满容器，把安全区限制在操作 UI，并针对超宽比例适配画面。仅删除 CSS padding 不能消除 Godot 的 16:9 留边；强行横向拉伸会改变角色和饭盒比例。当前 RC7 **没有**声称修复手机全屏，也未改动玩法布局或 Toy 线上版本。
